# Testing & QA Skill（for Agents）

## 适用场景
- 单元测试、集成测试、端到端测试、Mock/Stub 设计
- 回归验证与缺陷复现路径梳理

## 核心原则

1. **测试先写可复现步骤**：先明确输入、预期、边界，再实现。
2. **小单元可隔离**：优先稳定、快速、可重复的单元测试。
3. **覆盖关键路径**：优先覆盖支付、鉴权、持久化、外部调用这些高风险环节。

## 强制执行清单

- 新增/改动逻辑尽量配套最小测试。
- 异步与并发场景增加超时与并发边界测试。
- 失败用例必须有明确断言（不是只断言 `status == 200`）。
- 外部依赖测试应通过 mock/stub 隔离，避免脆弱集成。
- CI 中要有可复现入口（最小集合 + 全量集合）。

## 推荐实践

- 采用 Given/When/Then 或 Arrange-Act-Assert。
- fixture 使用共享工厂，避免重复初始化开销和跨测试污染。
- 对关键流程记录回归脚本（复现命令 + 核心断言）。
- 发现 flaky 测试时先修复环境与数据稳定性，再谈算法。

## 常用质量门禁

- 项目标准测试命令（如 `go test ./...`/`pytest -q`/`cargo test` 等）
- 覆盖率命令（如有）并结合重点模块门限
- 慢测试报告与失败重试策略（避免将 flaky 当稳定测试）

## 反模式（避免）

- 只验证“成功路径”，忽略空值、非法输入、超时、重试。
- 测试中直接依赖真实第三方服务。
- 依赖执行顺序的测试（测试互相污染）。
- 无意义断言：只 `print` 不 assert。

## 与仓库冲突时的优先级

- 以项目测试框架、覆盖率与 CI 脚本为准。
- 与本文件冲突时，按项目真实测试策略和资源预算执行。
