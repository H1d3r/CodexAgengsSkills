# 低上下文子代理工作流

## 派单决策

- 用户或项目明确授权委派、且当前宿主实际支持时，优先把独立探索、审查、日志分析、局部实现或验证交给 sidecar 子代理；sidecar 指主线程之外的有界执行，不保证文件系统隔离。
- 主线程保留目标、边界、关键决策与集成；立即阻塞下一步的 critical path 本地做，不为“尽可能委派”先派再空等。
- 小任务、交接成本高于收益、依赖未稳定或需要共享编辑时串行；确有上下文隔离收益时可顺序委派，不为并行而拆分。
- 委派授权不是写入、外部通信或发布授权；遵循上级规则。只用实际暴露且允许使用的子代理工具，不凭模型名或产品文档猜能力；能力不明时按需读 [agent-runtime-compat](../agent-runtime-compat/SKILL.md)。

## 最小上下文与所有权

- 减少主线程上下文不保证减少总 token；子代理独立执行可能增加总 token 消耗。
- 每单只给一个可验收目标、明确 cwd/基线、写集或只读标记、必要输入定位、约束及验证命令；首次派单按需读 [bounded 模板](references/bounded-dispatch.md)。
- 优先独立上下文与必要事实，不默认 full-history fork；只有延续历史确为必要且宿主支持时才继承历史。宿主强制继承时如实记录，不能承诺上下文已隔离。
- 输入用文件/符号/行范围和少量事实，避免整库、整段对话、全量日志。子代理先读所属路径规则，只加载本单命中的最小 skills 与必要 references，不继承父线程全部已读资料；缺关键输入再精准索取。
- 父/子及子/子写集不重叠；同一文件默认同一 owner。共享 manifest、锁文件、接口或依赖由父线程串行集成；新文件同样执行项目创建事件门禁。保护已有 dirty worktree，不覆盖其他协作者改动。
- 并发取决于宿主实际限制、可用资源和独立工作数量，使用够用的最少 worker；未知上限不猜数字、不批量试探。父线程继续非冲突工作，不重复子代理已承接的探索或实现。

## 回收与集成

- 使用宿主完成通知或有界等待；仅在结果成为依赖或状态需要处置时查看，沿用游标/状态版本。不反复短间隔 poll、不拉取完整中间历史、不复述无变化状态。
- 回传 compact results：结论、变更路径/符号、验证命令与退出状态、必要证据定位、风险/阻塞/未验证项；不把原始探索和长日志倒回主线程。
- 父线程核对实际 diff、所有权和接口，运行最小相关集成检查；子代理通过不等于整体通过，离线证据不等于真实环境验收。仅对证据缺口定向复查，不重做整单。
- 结果回收后用宿主支持的 close 释放已完成子代理；取消/失败也在保存必要证据后停止并关闭。无 close 能力则记录限制，不用删除 worktree 或归档用户聊天替代。

## 顺序回退与停止

- 工具缺失、委派不允许或不能安全隔离时，同样按 bounded 单在主线程顺序执行；解释回退原因，不虚构 spawn/wait/close、不新建用户聊天冒充内部 worker、不靠提升权限或改宿主配置恢复能力。
- 子代理不扩范围、不自行递归派单；发现共享写冲突或权限阻塞即停止越界动作并回报，由父线程重划所有权、串行处理或保留用户门禁。不得自动 commit、push、发布或部署。
- 达到验收条件、交付摘要并回收 worker 后停止；外部验收缺失明确标为未验证，不无限重派。

核对官方依据与适用边界时，按需读取 [sources](references/sources-and-routing.md)。
