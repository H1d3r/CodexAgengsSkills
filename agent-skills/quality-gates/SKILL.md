# 质量门禁与验收模板（Language Agnostic）

## 标准执行顺序（按优先级）

1. `readme`/配置确认：先读仓库级规则与约束文件
2. 变更最小化：核对本次只触碰目标范围
3. 本地验证：按项目命令或文件规则执行
4. 结果复核：确认没有破坏调用方与导出行为
5. 回退策略：记录若失败时可回滚范围

## 验证输出最少字段

每次修改尽量输出：

- **执行命令**：`xxx`
- **结果**：通过/失败 + 失败摘要（如有）
- **影响范围**：文件列表 + 关键行为变化
- **风险点**：未处理或有意保留的风险

## 可复用验收清单

- 结构/接口检查：是否引入 breaking change
- 安全检查：是否新增敏感信息（密钥、token、密码、会话）
- 异常检查：是否吞异常或去上下文化
- 可维护性：函数/文件行数是否仍可控
- 可重复性：重运行命令得到一致输出

## 典型失败场景（快速自检）

- 修改后无任何验证命令记录
- 仅修改了行为但没提“为什么需要"不这样做"”的边界
- 改文件后未确认是否受影响依赖/调用方
- 忽略多语言任务中的主导语言
