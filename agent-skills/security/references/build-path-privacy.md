# 构建路径隐私共用约束

配置 Go/Rust 发布构建、打包原生 SDK 或排查二进制路径泄露时，结合对应语言参考执行本文；也适用于 CGO、Rust 原生依赖及 C/C++ 编译链。普通业务代码修改不默认触发。

## 目标与范围

- 防止公开分发的可执行文件、静态库和动态库携带真实用户名、个人主目录、本机源码目录、依赖缓存目录及工具链安装路径。
- 允许中性源码路径、模块名、相对文件名及必要上游来源信息。不承诺完全隐藏项目结构、任意编码数据或独立用户名字符串。

## 接入原则

1. 先读取项目规则、manifest、release profile、CI 和实际构建入口，扩展已有构建器，不重复创建平行流程。
2. 区分本地诊断构建与可分发构建；发布入口必须执行路径防护和产物检查。构建器主动清理环境时，在其受控环境内注入参数，不能仅依赖外部环境变量。
3. 合并原有有效参数，保留既有优化、features、目标架构、链接参数、ABI 导出和 panic 行为，以及交叉编译 sysroot 和目标编译器。
4. 不修改用户全局 Go/Cargo 配置，不自动安装工具、部署、发布或更新历史产物资格。

## C/C++ 原生依赖

- 根据实际编译器和版本设置路径映射：GCC/Clang 可使用 `-ffile-prefix-map=FROM=TO`；MSVC 使用适配其版本的路径映射选项，不能把其他编译器的同名参数直接套用。
- 覆盖实际生效的 CFLAGS、CXXFLAGS、CGO_CFLAGS、CGO_CXXFLAGS、必要 CGO 链接参数及 target 变体；合并参数并保留其边界，不覆盖原有平台设置。
- 经 cc-rs 以 shell 转义形式传递 flags 时，启用相应解析，例如项目所用版本支持的 `CC_SHELL_ESCAPED_FLAGS=1`；验证空格路径确实作为单个参数传到编译器。target 变体与 host/target 参数按实际构建器规则处理。
- 不假定所有 native 构建系统都会读取这些变量。检查实际编译行为及 `__FILE__` 等产物来源；需要详细编译命令时在本地核对，不公开原始敏感日志。

## 预编译库与平台元数据

- 路径映射不能追溯修改预编译依赖，必须检查最终交付内容。
- Rust 静态 archive 可能包含预编译标准库的调试路径；必要时使用匹配目标格式的工具仅剥离调试信息，再验证真实链接及必要符号。不能用全量 strip 破坏 SDK 链接能力，也不直接替换二进制字节。
- macOS dylib 的 install name 可能含绝对输出路径，使用符合既有加载约定的中性 install name；保留其他必要加载及链接参数，并测试动态加载。
- 修改 Mach-O 前必须明确签名状态：已确认 unsigned 或 ad-hoc 时，才可处理本机构建的产物；修改后验证并按需刷新 ad-hoc 签名。正式签名不得覆盖；签名检查结果未知、工具失败或无法判断时停止修改，不能把失败视为 unsigned。
- ad-hoc 验证不得描述为 Developer ID 签名、公证或生产验收；正式签名产物需要走项目原有构建与签名流程。

## 发布产物门禁

1. 在 qualification（产物合格判定）、打包或分发前检查实际产物，包括缓存复用产物和预编译依赖。检查最终二进制、库、解包内容、平台元数据及受控保存的调试文件，不能只检查中间对象。
2. 扫描已知本机路径及 macOS、Linux、Windows 个人主目录模式，涵盖词法路径、解析后路径及分隔符变体。支持空格用户名、非 ASCII 用户名、UTF-8、UTF-16LE/BE 和跨读取块匹配。
3. 使用流式扫描，避免一次加载大型产物；跨块保留必要重叠数据或增量解码状态，不能因读取边界或编码边界漏检。压缩、归档及调试节区按实际格式检查；`strings` 只能用于初筛。
4. 检查失败返回非零状态，不授予产物合格资格。错误只输出固定分类，不打印匹配内容、原始敏感字符串或含敏感路径的底层异常；工具失败、结果不完整不能算通过。
5. 发现残留时修复编译参数、生成器或依赖后重建并复查；禁止直接替换二进制字节。真实私有路径在运行时获取，不作为固定测试数据提交。
6. 调试符号、PDB/dSYM、原始日志和私有构建收据不得随公开包分发；按既有诊断策略受控保存，且仍需检查其中的敏感路径。
7. 扫描通过仅证明所检查模式未命中，不能代替完整信息泄露审计，也不能保证任意编码数据或独立用户名字符串均已排除。

## 验证与交付

只运行与改动相关的检查；实现或修改对应构建逻辑时，最小验证覆盖适用场景：

- 参数合并、实际优先级、清理环境后的参数注入，以及 linker、SONAME、页面对齐等平台参数保留。
- 空格路径、非 ASCII / 外国用户名、UTF-16LE/BE、跨块匹配及中性路径对照；发现残留后拒绝 qualification，错误输出不包含敏感原值。
- 实际编译后的 `file!()`、`__FILE__`、`runtime.Caller` 或等效来源；环境变量字面值、生成代码和资源中的真实路径单独移除或拒绝。
- 静态 SDK 的真实链接、动态库加载及必要 ABI 导出，不能以符号列表检查代替实际调用方验证。
- 涉及 Mach-O 修改时，覆盖明确 unsigned、ad-hoc、正式签名和未知状态分支；仅前两种可修改，并验证修改后的签名状态。

构建逻辑拆为共享 helper 时，将 helper 纳入现有构建输入固定和来源记录机制。

区分配置测试、编译器 fixture、完整产品构建及真实平台验收；交付时说明覆盖的入口、已验证产物及未验证平台。旧二进制、旧哈希和旧验收记录不得自动继承新约束，需重新构建、扫描并按原流程验收。
