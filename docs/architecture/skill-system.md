# Agent Skill System v3

## 目标

本系统使用高信号 `AGENTS.md`、原生 Skill Bundle、机器可读路由和只读检查器，让不同 Agent 在不全量加载规则的前提下获得稳定约束。

## 读取顺序

1. 运行时加载根或祖先目录的 `AGENTS.md`。
2. 从任务文本、目标文件、项目事实和事件解析路由。
3. 按 `P1` 语言/框架、`P2` 技术域、`P3` 方法学及显式优先级加载最小集合。
4. 仅在 skill 命中后读取其 `SKILL.md`。
5. 只有当前任务需要时才读取 `references/` 或运行 `scripts/`。

`agent-skills/AGENTS.md` 只在维护技能库本身时生效，不进入普通任务的固定读取链。

## 路由模型

`skill-routing.json` 的 `skills` 节点同时声明路径、层级、优先级、文本触发、事件触发、依赖、冲突和兼容宿主。路由器执行：

1. token 与别名归一化；
2. 关键词、短语、事件和项目事实匹配；
3. 递归补齐依赖与组合规则；
4. 确定性解决冲突；
5. 按层级和优先级稳定排序；
6. 输出路径及逐 skill 命中原因。

## 文件创建门禁

任何新文件、新目录或生成产物都必须先触发 `project-structure`。该 skill 先检测项目事实，再分类内容，最后选择路径。历史结构只报告，不在无关任务中自动搬迁。

## 扩展 Skill

新增 skill 时：

1. 创建 `<name>/SKILL.md`，frontmatter 名称与目录一致；
2. 将长说明拆入按需读取的 reference；
3. 在路由清单注册触发器和显式优先级；
4. 增加至少一个命中和一个冲突或不误触发用例；
5. 运行路由检查、回归和单元测试。

## 兼容策略

核心规则按能力而非型号判断：是否允许写入、是否处于规划模式、可用工具、网络与审批、是否支持子代理、异步工具调用和中途引导。已知宿主或模型 profile 只能补充已验证信息，不能扩大授权。
